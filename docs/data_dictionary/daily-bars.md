# Data dictionary: instruments, daily bars and snapshots

Last updated: 2026-11-14 (Phase 1). Source of truth for types is
`quantlab/data/schemas.py`.

## Instrument

| Field | Type | Meaning |
|---|---|---|
| `instrument_id` | UUID string | Stable internal identity. Never changes, never reused |
| `exchange` | `NSE`, `BSE` | Listing exchange |
| `instrument_type` | `EQUITY`, `ETF`, `INDEX` | |
| `currency` | `INR` | Quote currency |
| `symbols` | list of symbol periods | See below |

### Symbol period

A display identity in effect over a date range. Both dates are inclusive.

| Field | Meaning |
|---|---|
| `symbol`, `name`, `isin` | As stated by the source. `name` and `isin` may be null |
| `valid_from` | First date the symbol applies. Required |
| `valid_to` | Last date it applies. Null means still in effect |
| `source_id` | Which source stated it |

Periods of one instrument from one source may not overlap. A recorded period can gain an
end date or fill in a missing name/ISIN; any other contradiction fails the ingestion.

## Daily bar

| Field | Type | Meaning |
|---|---|---|
| `instrument_id` | string | Internal instrument ID |
| `exchange` | enum | |
| `trading_date` | date | Exchange session date |
| `open`, `high`, `low`, `close` | Decimal(20, 6) | Price in `currency`, on the stated `adjustment_basis` |
| `volume` | int64 | Shares traded |
| `turnover` | Decimal(24, 4), nullable | Traded value in `currency`. Null when the source has none |
| `source_id` | string | Provider/source identifier |
| `source_record_id` | string, nullable | Where the record sits in the source (for CSV: file and line) |
| `retrieved_at` | UTC timestamp | When the raw payload was first retrieved |
| `source_as_of` | UTC timestamp, nullable | The source's own as-of time, when it exposes one |
| `currency` | enum | |
| `adjustment_basis` | enum | `UNADJUSTED`, `SPLIT_ADJUSTED`, `SPLIT_AND_DIVIDEND_ADJUSTED`, `UNKNOWN` |
| `schema_version` | string | Currently `1` |

Values with more decimal places than the storage type are quarantined, not rounded.

## Validation rules

A source record is either accepted or quarantined with every reason that applies. Nothing is
dropped or repaired. A record is quarantined when:

- its instrument is missing or not in the source's instrument list;
- `trading_date`, a price, `volume` or a present `turnover` is missing or unparseable;
- a price is not finite or not positive; volume or turnover is negative; volume is not whole;
- a value exceeds the storage precision or range;
- `low > min(open, close)` or `high < max(open, close)` (tolerance: zero);
- `trading_date` is after the retrieval date;
- it duplicates another record's instrument and date. Identical repeats keep the first copy;
  repeats that disagree are all quarantined.

Reported as quality warnings on the snapshot, not quarantined:

- bars dated Saturday or Sunday (NSE holds occasional weekend sessions);
- weekdays with no bar inside an instrument's date range;
- an `UNKNOWN` adjustment basis.

An ingestion in which no record is accepted fails and publishes nothing. Its quarantine
report stays available through the ingestion run.

## Snapshot manifest

One per published snapshot, stored in the catalog and as `manifest.json` beside the data.
Fields: snapshot and dataset IDs, version, source, provider name, licence reference, data
classification, source dataset version, extraction and creation times, date range,
instrument IDs, record and quarantined counts, schema and normalizer versions, adjustment
basis and methodology, input fingerprint, content checksum, file checksums, raw object
references, weekday gaps and quality warnings.

`content_sha256` is computed over the canonical text of every bar in order, so it does not
depend on Parquet encoding or library versions.

Data classification:

| Value | Meaning |
|---|---|
| `SYNTHETIC_TEST_DATA` | Generated by code. Not market data. Never valid in a performance claim |
| `USER_SUPPLIED` | Files supplied by the user, who is responsible for the right to use them |
| `LICENSED` | Obtained under the licence named in `licence_reference` |

## CSV input format

UTF-8, comma-separated, header row required. Dates are `YYYY-MM-DD`. Prices are INR.

`instruments.csv`: one row per symbol period.

```text
provider_instrument_id,exchange,instrument_type,symbol,name,isin,valid_from,valid_to
```

`name`, `isin` and `valid_to` may be empty. `provider_instrument_id` is your own stable key
for the instrument; use the same key across deliveries so the instrument keeps its identity
through symbol changes.

`daily_bars.csv`: one row per instrument per date. `turnover` is an optional column.

```text
provider_instrument_id,trading_date,open,high,low,close,volume,turnover
```

A structurally broken file (missing columns, not UTF-8) fails the ingestion. A broken row
is quarantined.

## Point-in-time limitations

- There is no exchange calendar. Holiday gaps and missing data look the same.
- There are no corporate actions. A dataset declared `UNADJUSTED` has price discontinuities
  at splits and bonuses; one declared adjusted reflects the supplier's adjustment as of its
  delivery date, which embeds later knowledge into earlier prices.
- There are no index constituents, so no historical universe can be built yet.
- Delisted instruments are present only if the supplied files include them. A file of
  currently listed stocks is survivorship-biased and QUANTLAB cannot detect that.

Research built on this layer alone is data-limited in the sense of spec section 5.4.
